# CLAUDE.md — erosita-desi-aion-flow (working notes for the agent)

Project: predict eROSITA X-ray properties + host stellar mass from DESI optical/WISE/imaging via a normalizing-flow head on frozen AION embeddings. Extends the PAI26 paper with a **cleaned crossmatch** and **uncertainty-aware, per-target** training.

## LIVING DECISIONS LOG — keep it updated (required)
`docs/decisions.md` records every load-bearing decision with exact, data-verified formulas: crossmatch/NWAY cleaning (what was cut and why), target definitions (esp. HR32 band rates + arctanh transform), error construction and use (split-normal, convolution likelihood, spectype floors), architecture choices, and the **run registry with per-run performance**. Any change to matching, targets, errors, or architecture updates this file in the same commit; **any completed run gets its results row filled in.**

## LIVING PIPELINE DOC — keep it updated (required)
`docs/pipeline.md` is the source of truth for the full experiment flow: data sources & download, crossmatch & cleaning, targets & error models, architecture, training & eval, status. It is **illustrated** (slide-like) with figures in `docs/figures/` generated by `docs/make_pipeline_plots.py` (architecture, paper results, NWAY cleanup, error treatment, targets; Okabe-Ito CVD-safe palette). **Whenever the pipeline changes** (a new data source, a change to matching/cleaning, an error model, the architecture, the split logic, a headline result / new metrics), you MUST, in the same change:
1. update `docs/pipeline.md`;
2. if numbers/plots changed, regenerate figures: `python docs/make_pipeline_plots.py`;
3. re-render the PDF: `python docs/render_pipeline_pdf.py` → `docs/pipeline.pdf`.
So `docs/pipeline.pdf` always reflects reality, with current plots.

## Load-bearing invariants
- **Leakage safety:** train/val/test split strictly by unique `desi_targetid`; no targetid crosses splits.
- **Re-split after cleaning:** derive the split on the *cleaned + deduped* sample (NWAY keep + one row per targetid), not before.
- **Uncertainty:** targets use the split-normal error model via the convolution likelihood (`--error-mode convolve`); HR in arctanh space, IG-primary.
- **Provenance sidecars** (built from the eROSITA×DESI catalogs, NOT flatiron — flatiron/PROVABGS is a different object set, ~0.4% overlap): `../stanford_deadline/data/match_quality.csv` (NWAY clean filter) and `../stanford_deadline/data/targets_extra.csv` (targets + errors).
